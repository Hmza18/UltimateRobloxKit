# URK VFX textures

Particle, beam and UI effect textures generated by the kit. They are original work: every pixel comes from the maths in `tools/vfx/textures.py`, with no third-party art, packs or fonts involved. They are MIT licensed like the rest of the repository (see [LICENSE](../../LICENSE)).

| Folder | What |
|---|---|
| `textures/` | 22 single textures, white on transparent |
| `flipbooks/` | 3 sprite sheets for `ParticleEmitter` flipbooks |
| `manifest.json` | Key, file, size, bytes, hashes, description and `assetId` for each |

All of them are white so `ParticleEmitter.Color`, `Beam.Color` or `ImageColor3` sets the colour. Transparent pixels keep white RGB, which avoids a dark fringe when the engine filters the image.

## Rebuild

```bash
python3 tools/vfx/textures.py
```

```bash
python3 tools/vfx/textures.py --check
```

The build is deterministic. Do not edit the PNGs by hand: change the shape function and rebuild.

## Upload is a manual step

The kit does not upload anything and has no Roblox credentials. `assetId` is `null` for every texture until the owner of the game uploads the files with their own Roblox account (Creator Hub, or the Asset Manager in Studio) and records the ids with `tools/vfx/assetmap.py`. The steps are in [docs/workflows/visual-assets.md](../../docs/workflows/visual-assets.md).

Until then effects use Roblox's built-in particle textures, so nothing here is required for the visuals kit to run.

## Not verified

The files are valid 8-bit RGBA PNGs with power-of-two sizes, checked by `tests/test_visuals_tools.py`. How they look as particles in Roblox, and whether Roblox moderation accepts each upload, is `NEEDS MANUAL REVIEW`: none of them has been uploaded or rendered in Studio.
